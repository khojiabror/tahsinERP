1. О модуле

1.1. Назначение

Модуль состоит из двух частей. Управление задачами — руководитель или коллега поручает сотруднику работу (кто делает, к какому сроку, насколько важно), исполнитель обновляет статус, а руководитель по канбан-доске и дашборду видит загрузку и исполнительскую дисциплину всей команды. Документооборот — официальные письма предприятия (исходящие и входящие), приказы и внутренние стандарты ведутся в едином реестре с автоматической нумерацией, этапами согласования и формированием документа по шаблону Word.

В результате ни одно поручение не остаётся «устным», нарушение срока сразу видно, номера писем не повторяются, а все документы выходят на едином бланке.

1.3. Связь с другими модулями

Справочники задач (статус, приоритет, проект) заполняют форму задачи; смена статуса сразу отражается на канбане, дашборде, значке в шапке и показателях главной страницы. В документообороте шаблоны Word (DocTemplates) общие для официального письма, приказа и стандарта; из письма формируется «документ Word», который сохраняется как версия. Должностные инструкции находятся в том же меню («Управление документами»), но относятся к кадрам и описаны в руководстве 09-HR.

5. Работа с задачами

5.1. Создание задачи

Пример: поручить менеджеру по логистике растаможку партии из 120 мониторов, срок 30 октября, приоритет «Важно», проект «Аксессуары: ассортимент 2027».

1.В списке Задачи → Задачи нажмите Добавить задачу.

2.① Title — короткий заголовок-результат (с глаголом): «Оформить на таможне партию мониторов Samsung».

3.② Описание — что, сколько, по какому критерию принимается (правило SMART, раздел 9.1).

4.③ Статус — по умолчанию «Запланировано» (TODO). ④ Приоритет — «Важно».

5.⑤ Ответственный — исполнитель (в списке только активные пользователи). ⑥ Проект — при необходимости.

6.⑦ Срок — 30.10.2026. ⑧ Сохранить — система присвоит код (ACC-8) и откроет карточку задачи.

Рис. 10. Форма создания задачи (заполнена)

Примечание: Код присваивается при сохранении: код проекта + «-» + наибольший номер по этому префиксу + 1 (после ACC-7 — ACC-8). Расчёт идёт в базе данных под блокировкой — даже при одновременном сохранении коды не повторяются. Автор и время создания записываются автоматически.

5.3. Смена статуса с комментарием

Исполнитель меняет статус, когда начинает работу, сдаёт результат или упирается в препятствие, и оставляет короткий комментарий. Комментарии не удаляются — каждый добавляется ниже предыдущих с датой, временем и автором (аудиторский след).

1.В списке нажмите ⑧ (круговая стрелка) или в карточке Сменить статус.

2.① Выберите новый Статус: «В работе».

3.② Напишите Комментарий: что сделано и что осталось.

4.③ Сохранить — откроется карточка задачи.

Рис. 12. Форма смены статуса

Рис. 13. После смены статуса: ① новый статус, ② история комментариев

Внимание: Обязательной последовательности статусов нет: из любого статуса можно перейти в любой (например, из «Выполнено» обратно «В работе» — переоткрытие). Для смены статуса достаточно права просмотра страницы «Смена статуса» — исполнитель может обновлять свою задачу без права на её редактирование.

6.1. Создание исходящего письма

Пример: коммерческое предложение ООО «ТехноМаркет Ташкент» на компьютерные аксессуары.

Рис. 19. Форма нового исходящего письма

1.Нажмите Новое письмо. ① Номер письма (Maktub raqami) предлагается автоматически.

2.Укажите дату, ② направление (Chiqish — исходящее), ③ канал (EMAIL, LETTER — почта, COURIER, FAX).

3.④ Внешняя компания, контактное лицо и его должность; при необходимости наш исх. номер (TK-2026/42) и их номер (для ответа).

4.⑤ Тема и обращение («Уважаемый Сергей Петрович!»).

5.⑥ Основной текст с форматированием. ⑦ Предложить текст (Matn taklif qilish) — система подготовит типовой текст по введённым реквизитам; отредактируйте его.

6.⑧ Таблица товаров и цен (для коммерческого предложения): наименование, размер, цена EXW, EXW с НДС, CIP, CIP с НДС. Добавить товар — новая строка.

7.⑨ Сохранить — письмо создаётся в статусе «Черновик».

Стандарт: Incoterms® 2020: EXW (Ex Works) — товар передаётся на складе продавца, перевозка за счёт покупателя; CIP (Carriage and Insurance Paid To) — продавец оплачивает перевозку и страхование до указанного пункта. Поэтому цены указываются для обоих условий отдельно.


Цена с НДС вводится отдельно (система её не рассчитывает). Ставка НДС в Узбекистане — 12%, проверочная формула:

Цена с НДС = Цена без НДС × (1 + 0,12)

Пример: 85 000 × 1,12 = 95 200 сум; 340 000 × 1,12 = 380 800 сум

9.3. Практический сценарий: недельный цикл контроля

1.Понедельник — планирование. Открывается проект (WMS), работа делится на SMART-задачи, каждой — один исполнитель, срок и приоритет.

2.Ежедневно — исполнитель. Начал — «В работе», препятствие — комментарий, закончил — «Выполнено» и комментарий о результате.

3.Ежедневно — руководитель (5 минут). Канбан «По статусам»: залежавшиеся карточки в «Запланировано», красные сроки. В списке — фильтр Просроченные.

4.Пятница — анализ. Дашборд: доля просроченных, уровень выполнения в срок, рейтинг сотрудников. Выгрузка в Excel для планёрки.

5.Меры. При систематических срывах — уменьшить объём задач, пересмотреть приоритеты или добавить ресурс; согласованный перенос срока фиксировать в комментарии.

Примечание: Поскольку обычный пользователь видит только свои задачи, руководителям, которые ставят задачи другим и контролируют их, нужна роль Администратор (либо администратор готовит выгрузку Excel по исполнителям). Это ограничение действует в версии 2026-10.

10.3. Интерпретация для CEO

•Доля просроченных > 20% — планирование нереалистично или нагрузка неравномерна: сравните рейтинг сотрудников и «Последние 7 дней».

•Выполнение в срок < 80% — сроки ставятся без согласования или о препятствиях сообщают поздно (смотрите комментарии).

•Растёт доля «Запланировано» — задачи ставятся быстрее, чем выполняются: расставьте приоритеты для новых задач.

•График просроченных по проектам показывает, какому проекту нужно внимание.

•Используйте рейтинг не для наказания, а для перераспределения нагрузки: у сотрудника с большим числом задач срывов естественно больше.

Примечание: Главная страница и значок в шапке определяют «открытые» и «просроченные» задачи только по коду DONE — задача в статусе «Отменено» для них ещё открыта. Дашборд задач определяет закрытость по IsFinal. Поэтому цифры могут немного расходиться; официальным источником считайте дашборд задач.

11.3. FAQ

•Можно ли поставить задачу нескольким сотрудникам? — Нет, один исполнитель (роль «R» в RACI). Разбейте работу на части, создайте отдельные задачи и привяжите их к одному проекту.

•Приходит ли исполнителю уведомление? — Исполнитель видит задачу по счётчику в шапке и в списке «Задачи»; уведомлений по почте/Telegram в ERP нет.

•Может ли исполнитель сам изменить срок? — При наличии права редактирования — да. Поэтому сделайте правилом обоснование переноса в комментарии.

•Почему названия статусов на узбекском в русском интерфейсе? — Названия справочников хранятся в базе на одном языке; в Настройках их можно записать на любом языке.

•Нужно исправить утверждённое письмо? — Статус утверждённого письма не меняется; создайте новое исправленное письмо (старое останется в истории).

•Изменятся ли старые документы при обновлении шаблона? — Нет, созданные файлы Word сохранены как версии; новый шаблон применяется только при следующем формировании.

11.4. Советы

•Начинайте заголовок задачи с глагола и формулируйте результат («Оформить …», «Утвердить …»).

•Выбирайте короткий осмысленный код проекта (ACC, WMS) — по коду задачи сразу понятно, к какому проекту она относится.

•В каждом исходящем письме указывайте наш исх. номер, в ответах — их номер.

•При смене бланка не удаляйте старый шаблон, а архивируйте его.
