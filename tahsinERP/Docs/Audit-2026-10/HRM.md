## Cross-module notes

1. **FIN_TRANSACTIONS.Direction** has no enum. HR uses 1 for expenses while Finance uses 1 for inflow (HRM-B01). Add a shared `FinDirection` constant class and use it in every module that posts to Finance.
2. **Public / anonymous endpoints** (Koreshok + web.config `<location>`): security review across modules for other `[AllowAnonymous]` and `allow users="*"` locations.
3. **Number generation** (TabNo, JD codes): needs a shared, concurrency-safe numbering service (SQL SEQUENCE) and unique indexes.
4. **Document files** (DOC_FILES download by id): JobDesc reimplements DownloadFile, MIME mapping and template handling. These belong in a shared Documents service with doc-type permission checks (IDOR, HRM-S05).
5. **Lookup caching**: org units, positions, currencies and products are reloaded on every HR page. A shared cached `LookupService` would help every module.
6. **State-change via GET** (Approve, Close) and `Html.Raw` JS serialization are probably repeated in other modules. Add a lint or grep rule.
7. **Runtime DDL** (`EnsureTable`) pattern: check other services for `IF OBJECT_ID ... CREATE TABLE` and replace them with migrations.
8. **View-level `Response.Redirect` permission checks** and per-page CDN script tags: a layout-wide cleanup (bundling).
9. `SoftDeleteReferenceService` exists. The HR soft-deletes of header plus lines (D12) could use it consistently, and every "has related payroll" check must filter `IsDeleted`.
10. DbContext: every HR controller holds a field `db` and disposes it, except **HrEmployeeHistoryController (no Dispose)**. JobDescController creates 2+ contexts per request (`LoadHRJobDescriptions` opens its own).
